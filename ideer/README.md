# Idéer och metod

**För det som inte är ett verktyg.**

`tools/` bär saker man installerar eller anropar. Men mycket av det som är värt att spara är
inte det: arbetssätt, principer, sådant någon lärt sig den hårda vägen, tips om hur man tar
sig fram som ingenjör. Det hörde tidigare ingenstans, och hamnade därför ingenstans.

## Vad som hör hemma här

- Arbetssätt och metod som inte redan är ett körbart flöde
- Principer och tumregler
- Karriär, lärande, hur man tänker kring problem
- Idéer om produkter eller funktioner som inte hör till ett specifikt projekt

## Vad som INTE hör hemma här

| Det här | Bor här i stället |
|---|---|
| Något man installerar eller anropar | `tools/` |
| Ett arbetssätt som körts skarpt minst en gång | `workflows/` |
| Text som klistras in i `CLAUDE.md` | `rules/` |
| Statusen för ett projekt | `projects/` |

## Samma regel som överallt annars

**Ett obligatoriskt fält: vad talar emot.** En idé utan invändning är inte utvärderad, den är
bara omtyckt. Det gäller lika mycket för ett arbetssätt som för ett npm-paket.

Och som i `analysmall.md`: **fakta är projektoberoende, tillämpningen är det inte.** En princip
kan vara sann och ändå fel för ett visst projekt.
